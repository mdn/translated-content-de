Der Erfolg und das Wachstum des MDN-Web-Docs-Projekts sind zu einem großen Teil unserer Community von Mitwirkenden zu verdanken. Einige Mitwirkende haben einen Teil ihrer Zeit dafür eingesetzt, bei den täglichen Aufgaben zum Betrieb von MDN Web Docs zu helfen. Änderungen an der Website, einschließlich Wartungsaufgaben, werden von Mitarbeitenden, Auftragnehmenden und einem Netzwerk von Partnern vorgenommen, die sich alle der Gesundheit, dem Wachstum und der Wartung von MDN Web Docs widmen. Das Projekt stützt sich stark auf [Rollen](#rollen) und [Teams](#teams) in der [MDN-Organisation auf GitHub](https://github.com/mdn), um Änderungen dieser verschiedenen Gruppen zu verwalten und zu übernehmen. Eine Liste der aktuellen Mitglieder der Organisation finden Sie unter [github.com/orgs/mdn](https://github.com/orgs/mdn/people).

Beiträge der Community helfen diesem Open-Source-Projekt enorm.
Mitwirkende können ihre Arbeit an MDN Web Docs nutzen, um ihre Fähigkeiten im Schreiben, in Technik und Zusammenarbeit sowie ihre Fähigkeit zur Zusammenarbeit mit Menschen unterschiedlicher Hintergründe zu demonstrieren. Dieser Abschnitt beschreibt die Rollen, die Sie bei einer freiwilligen Mitarbeit am MDN-Web-Docs-Projekt übernehmen können.

## Rollen

Im MDN-Web-Docs-Projekt können Sie die Rolle eines [Mitwirkenden](#mitwirkender), eines [Organisationsmitglieds](#organisationsmitglied), eines [Maintainers](#maintainer) oder eines [Owners](#owner) übernehmen. Der Übergang von einer Rolle zur nächsten erfolgt schrittweise.
Mit zunehmender Verantwortung können Sie gleichzeitig mehr als eine Rolle ausüben.
Rollen wie die des [eingeladenen Experten](#eingeladener_experte) können direkt übernommen werden, wenn Sie Fachwissen in einem bestimmten Bereich nachgewiesen haben.

Unabhängig von der Rolle, die Sie in diesem Projekt übernehmen, sind Sie immer ein [Mitwirkender](#mitwirkender).
Ein **Mitwirkender** ist die grundlegende Rolle, auf der alle anderen Rollen aufbauen.
Daher müssen Sie bei jeder Mitarbeit an diesem Projekt die Anforderungen der Rolle als Mitwirkender erfüllen.

### Mitwirkender

Mitwirkende oder _Community-Teilnehmende_ leisten mit ihrer Zeit, ihren Fähigkeiten, Meinungen und Ideen einen Beitrag zum Projekt.
Mitwirkende arbeiten direkt am Projekt und schaffen Mehrwert.
Neben dem Schreiben und Testen von Code umfassen Beiträge das Erstellen und Aktualisieren von Dokumentation, Recherche, Fehlerbehebungen und die Unterstützung anderer Community-Mitglieder.

Abhängig von der Häufigkeit Ihrer Beiträge können Sie gelegentlich mitwirken oder ein aktiver Mitwirkender sein.
Wenn Sie großen Einfluss auf das Projekt ausüben, können Sie als [besonders hervorgehobener Mitwirkender](#besonders_hervorgehobener_mitwirkender) nominiert oder zum [Organisationsmitglied](#organisationsmitglied) befördert werden.

Wenn Sie neu hier sind und Mitwirkender werden möchten, werfen Sie einen Blick auf unseren [Leitfaden für die ersten Schritte](/de/docs/MDN/Community/Getting_started) und die [Repositories in der MDN-GitHub-Organisation](https://github.com/orgs/mdn/repositories).

Als Mitwirkender können Sie sich durch die folgenden Aktivitäten am Projekt beteiligen:

- Teilnahme an Community-Diskussionen in den [Kommunikationskanälen](/de/docs/MDN/Community/Communication_channels).
- Unterstützung anderer Mitwirkender bei ihren Pull Requests und Issues oder Mentoring neuer Mitwirkender.
- Einreichen von Fehlerberichten. Weitere Informationen finden Sie unter [den wichtigsten Repositories](/de/docs/MDN/Community/Our_repositories).
- Kommentieren von Issues, um Diskussionen einer produktiven Lösung näherzubringen.
- Bearbeiten offener Issues (beispielsweise im Repository [`content`](https://github.com/mdn/content/issues)) durch Einreichen von [Pull Requests](/de/docs/MDN/Community/Pull_requests).
- Teilnahme an Community-Veranstaltungen.
- Unterstützung bei der Förderung des MDN-Projekts.

**Anforderungen:**

Um Mitwirkender zu sein, müssen Sie Folgendes befolgen:

- [Mozillas Verhaltenskodex](https://www.mozilla.org/en-US/about/governance/policies/participation/)
- Die spezifischen Richtlinien für jedes Repository. Falls es projektspezifische Hinweise oder Richtlinien gibt, finden Sie diese in einer Datei `CONTRIBUTING.md` im Stammverzeichnis des Projekt-Repositorys.

**Berechtigungen:**

Mitwirkende haben die folgenden Berechtigungen:

- Einladungen zu Veranstaltungen für Mitwirkende.
- Berechtigung, Organisationsmitglied zu werden.

### Organisationsmitglied

[Organisationsmitglieder](https://github.com/orgs/mdn/people) sind etablierte [Mitwirkende](#mitwirkender), die regelmäßig am MDN-Web-Docs-Projekt teilnehmen und dazu beitragen.
Von ihnen wird erwartet, dass sie im Interesse des Projekts handeln.

**Anforderungen:**

Um Organisationsmitglied zu sein, müssen Sie eine oder mehrere der folgenden Anforderungen erfüllen:

- Sie haben zwei oder mehr Pull Requests eröffnet, die zusammengeführt wurden und zwei oder mehr Issues lösen.
- Sie haben mindestens zwei Monate lang zu MDN-Web-Docs-Projekten beigetragen.
- Sie haben aktiv zu mindestens einem Projektbereich beigetragen.

Die folgenden beiden Anforderungen sind verpflichtend:

- Sie haben [Zwei-Faktor-Authentifizierung](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication) für Ihr GitHub-Konto aktiviert.
- Sie haben [signierte Commits](https://docs.github.com/en/authentication/managing-commit-signature-verification/signing-commits) aktiviert.

**Berechtigungen:**

Organisationsmitglieder haben Berechtigungen auf [Organisationsebene](https://github.com/mdn) bei GitHub.

### Maintainer

Maintainer sind etablierte [Mitwirkende](#mitwirkender), die für ein oder mehrere Projekte bei MDN verantwortlich sind.
Von ihnen wird erwartet, dass sie an Entscheidungen über die Richtlinien und Prioritäten des Projekts mitwirken. Informationen zur Nominierung einer Person als Maintainer finden Sie im [Verfahren](#einen_maintainer_nominieren).

Als Maintainer beteiligen Sie sich an den folgenden Aktivitäten:

- Festlegen der Prioritäten für das Projekt, für das Sie verantwortlich sind.
- Teilnahme an Community-Meetings.
- Mentoring neuer und bestehender Mitwirkender in allen anderen Rollen.
- Abhängig von Ihren Fähigkeiten in Ihrem Projektbereich Vorschläge machen, genehmigen oder umsetzen für:
  - Verbesserungen an Code und Infrastruktur
  - Verbesserungen von Inhalten
  - Prozessverbesserungen

**Anforderungen:**

Um als Maintainer infrage zu kommen, müssen Sie eine oder mehrere der folgenden Anforderungen erfüllen:

- Sie haben mindestens sechs Monate Erfahrung als [eingeladener Experte](#eingeladener_experte) gesammelt.
- Sie haben umfassende Kenntnisse des Projekts über mehrere Bereiche hinweg nachgewiesen.
- Sie haben die Fähigkeit nachgewiesen, unabhängig vom Einfluss anderer Mitglieder Entscheidungen zum Wohl des Projekts zu treffen.
- Sie haben die Fähigkeit gezeigt, andere Mitwirkende zu betreuen.
- Sie haben sich verpflichtet, mindestens 16 Stunden pro Monat für die Arbeit am Projekt aufzuwenden.
- Sie haben am Community-Meeting teilgenommen, das alle zwei Monate stattfindet.

> [!NOTE]
> Wenn Sie jemanden kennen, der Ihrer Meinung nach für diese Rolle infrage kommt, können Sie [einen Maintainer nominieren](#einen_maintainer_nominieren).

**Berechtigungen:**

Maintainer haben die Berechtigung, Pull Requests zu genehmigen und zusammenzuführen.

### Owner

Owner haben umfassende Berechtigungen zur Verwaltung von Benutzern und [GitHub-Teams](https://github.com/orgs/mdn/teams), zur Pflege des Zugriffs auf Repositories in der [MDN-Organisation](https://github.com/mdn), zur Verwaltung von Repository-Einstellungen und zur Bereitstellung in der Produktionsumgebung.
Owner sind an alle Anforderungen der anderen Rollen für Mitwirkende gebunden.

> [!NOTE]
> Die Rolle eines Owners ist derzeit auf Mozilla-Mitarbeitende beschränkt.

**Anforderungen:**

Zusätzlich zu den Verantwortlichkeiten der anderen Rollen für Mitwirkende haben Owner die folgenden Verantwortlichkeiten:

- Befolgen und Durchsetzen der Normen des MDN-Teams, einschließlich der [Community Participation Guidelines](https://www.mozilla.org/en-US/about/governance/policies/participation/) und der [Mozilla-Richtlinien](https://www.mozilla.org/en-US/about/governance/policies/).
- Befolgen der Richtlinien der MDN-Organisation und Vorangehen mit gutem Beispiel.
- Vorschlagen, Dokumentieren und Umsetzen neuer Richtlinien über den [Pull-Request-Prozess](/de/docs/MDN/Community/Pull_requests).
- Verfolgen und Mitwirken bei Issues und Diskussionen in der gesamten MDN-Organisation.
- Sicherstellen, dass ein Issue oder Pull Request innerhalb einer Woche Feedback von einem oder mehreren Mitgliedern erhält.
- [Archivieren](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories) oder Löschen nicht gewarteter Repositories.
- Besprechen von GitHub-Funktionen, Auswählen der zu verwendenden Funktionen und Dokumentieren von Entscheidungen.

**Berechtigungen:**

Owner können:

- Organisations-Owner und -Mitglieder nach Bedarf hinzufügen und entfernen.
- Mitarbeitende für bestimmte Repositories nach Bedarf hinzufügen und entfernen.
- Repositories nach Bedarf hinzufügen, entweder als neue Projekte oder durch Übertragungen.

## Besondere Rollen

Einige Rollen für Mitwirkende haben differenziertere Verantwortlichkeiten und besondere Voraussetzungen. Dazu gehören [besonders hervorgehobene Mitwirkende](#besonders_hervorgehobener_mitwirkender), [eingeladene Experten](#eingeladener_experte) und [Community-Manager](#community-manager).

### Besonders hervorgehobener Mitwirkender

Besonders hervorgehobene Mitwirkende sind Personen, die mit ihren Beiträgen zu MDN Web Docs Außergewöhnliches geleistet haben.
Ihre Beiträge erfolgen in Form von Pull Requests zur Verbesserung des Projekts, Unterstützung von Community-Mitgliedern in verschiedenen [Kommunikationskanälen](/de/docs/MDN/Community/Communication_channels) oder Lernforen oder durch Feedback zu GitHub-Issues und Pull Requests.

Einmal monatlich stellen wir einen besonders hervorgehobenen Mitwirkenden auf der [MDN-Website](/en-US/) vor.
Informationen zur Nominierung einer Person als besonders hervorgehobener Mitwirkender finden Sie im [Verfahren](#einen_besonders_hervorgehobenen_mitwirkenden_nominieren).

### Eingeladener Experte

Eingeladene Experten haben bei MDN durch ihre Beiträge, ihre Teilnahme an Diskussionen und Reviews oder durch nachgewiesenes Wissen in einem bestimmten Fachgebiet eine Erfolgsbilanz vorzuweisen.
Eingeladene Experten sind für einen bestimmten Themenbereich oder eine Komponente des MDN-Projekts verantwortlich.
Sie sind dafür verantwortlich, Pull Requests in ihrem Themen- oder Projektbereich zu überprüfen und zu genehmigen, technische Fragen zu beantworten und die allgemeine Gesundheit ihres jeweiligen Projekts zu erhalten. Informationen zur Nominierung einer Person als eingeladener Experte finden Sie im [Verfahren](#einen_eingeladenen_experten_nominieren).

Zusätzlich zu den Verantwortlichkeiten eines [Organisationsmitglieds](#organisationsmitglied) sind eingeladene Experten verantwortlich für:

- Das Befolgen des [Leitfadens für Reviews](https://github.com/mdn/content/blob/main/REVIEWING.md).
- Das Überprüfen von Pull Requests in ihrem Themenbereich.
- Die Unterstützung anderer Mitwirkender dabei, Reviewer zu werden.

Eingeladene Experten werden automatisch für ein Review zugewiesen, wenn Pull Requests in ihrem Themenbereich eröffnet werden.
Wenn es in einem Themenbereich mehr als einen Experten gibt, werden sie mithilfe einer [Lastverteilungsstrategie](https://docs.github.com/en/organizations/organizing-members-into-teams/managing-code-review-settings-for-your-team#about-auto-assignment) Pull Requests zugewiesen.

**Anforderungen:**

Um als eingeladener Experte infrage zu kommen, müssen Sie eine oder mehrere der folgenden Anforderungen erfüllen:

- Sie haben fundierte Kenntnisse eines bestimmten Themenbereichs nachgewiesen.
- Sie haben sich verpflichtet, für Ihren zugewiesenen Themenbereich verantwortlich zu sein.
- Sie haben neue und gelegentliche Mitwirkende unterstützt und dabei geholfen, Pull Requests für das Zusammenführen vorzubereiten.
- Sie haben am Community-Meeting teilgenommen, das alle zwei Monate stattfindet.

**Berechtigungen:**

Eingeladene Experten werden dem [Team der eingeladenen Experten](https://github.com/orgs/mdn/teams/invited-experts-and-co-maintainers) sowie dem entsprechenden Themen- oder Projektteam hinzugefügt. Eingeladene Experten können:

- Auf das erforderliche Repository für Commits sowie die Genehmigung und das Zusammenführen von Pull Requests zugreifen.
- Anderen Mitgliedern empfehlen und dafür stimmen, eingeladene Experten zu werden.
- Am wöchentlichen redaktionellen MDN-Web-Docs-Call teilnehmen.

### Community-Manager

Community-Manager haben in vielerlei Hinsicht eine eigene Rolle.
Community-Manager teilen viele der Verantwortlichkeiten eines [Maintainers](#maintainer).
Zusätzlich haben Community-Manager die folgenden Verantwortlichkeiten:

- Bearbeiten von Meldungen über Verstöße gegen unseren [Verhaltenskodex](https://github.com/mdn/mdn-community/blob/main/CODE_OF_CONDUCT.md), bei dem es sich um die [Mozilla Community Participation Guidelines](https://www.mozilla.org/en-US/about/governance/policies/participation/) handelt, sowie Entscheiden über angemessene Maßnahmen.
- Organisieren und Durchführen von Community-Veranstaltungen.
- Organisieren von projektbezogenen Community-Meetings.
- Festlegen von Medienstrategien zur Förderung des MDN-Projekts.
- Definieren und Umsetzen der Onboarding-Erfahrung für Mitwirkende.
- Onboarding neuer Mitwirkender und Benutzer.
- Sicherstellen der Gesundheit und des Wohlergehens des MDN-Projekts und aller Teilnehmenden.
- Ermitteln und Unterstützen bei der Umsetzung von Automatisierung zur Verbesserung der Nachhaltigkeit des Projekts.
- Treffen mit Mitwirkenden und Partnern sowie Sicherstellen einer gesunden Beziehung zu ihnen.
- Unterstützung bei der Triage von Issues und beim Review von Pull Requests, soweit angemessen.
- Überwachen aller [Kommunikationskanäle](/de/docs/MDN/Community/Communication_channels).
- Hervorheben von Mitwirkenden, die außergewöhnliche Arbeit geleistet und/oder ihr Engagement für das MDN-Projekt gezeigt haben.

### Zurücktreten oder Emeritus-Status beantragen

Im Leben kann sich viel ändern, und auch Ihr Engagement als Mitwirkender kann sich im Laufe der Zeit verändern. Abhängig von Ihrer Situation möchten Sie möglicherweise:

- Vorübergehend eine Pause vom Projekt einlegen.
- Zu einer weniger anspruchsvollen Rolle wechseln.
- Sich vollständig aus dem Projekt zurückziehen und einen Emeritus-Status beantragen.

In all diesen Situationen können Sie Ihre Situation und Ihr aktuelles Engagement gerne mit dem [MDN-Team](#das_mdn-team_kontaktieren) besprechen.

### Inaktive Mitwirkende herabstufen oder entfernen

Ein Mitwirkender kann herabgestuft oder als Mitwirkender entfernt werden, wenn Verantwortlichkeiten und Anforderungen nicht erfüllt werden, einschließlich wiederholter Inaktivität oder eines Verstoßes gegen den [Verhaltenskodex](https://github.com/mdn/mdn-community/blob/main/CODE_OF_CONDUCT.md).

Die Herabstufung oder Entfernung eines Mitwirkenden wird von einem Teilnehmenden während eines Maintainer-Meetings vorgeschlagen.
Der Teilnehmende liefert unterstützende Informationen für den Antrag auf Herabstufung oder Entfernung.
Nach einer Diskussion stimmen Maintainer und Community-Manager über die Angelegenheit ab, um eine Entscheidung zu treffen.

Das Entfernen inaktiver Mitwirkender schützt das Projekt und seine Ergebnisse und eröffnet zugleich neuen Mitwirkenden Möglichkeiten, sich einzubringen.

Wir definieren Inaktivität wie folgt:

- Keine Beiträge zum Projekt seit mindestens sechs Monaten.
- Keine Antwort auf Kommunikation seit mindestens drei Monaten.

Inaktivität schadet dem Projekt; sie kann zu unerwarteten Verzögerungen, zum Wegfall von Mitwirkenden und zu einem Vertrauensverlust in das Projekt führen. Mitwirkende müssen aktiv sein, um mit gutem Beispiel voranzugehen und ihr Engagement für das Projekt zu zeigen.

Bitte kommunizieren Sie mit dem Community-Team, um eine Herabstufung oder Entfernung zu vermeiden, falls sich Ihr zeitliches Engagement ändert; stattdessen können Sie proaktiv entscheiden, [für eine Weile zurückzutreten oder zum Emeritus-Status zu wechseln](#zurücktreten_oder_emeritus-status_beantragen).

## Teams

Wir verwalten Teams mithilfe der Funktion [GitHub-Teams](https://docs.github.com/en/organizations/organizing-members-into-teams/about-teams). Wenn Sie einem Team hinzugefügt werden, bedeutet dies, dass Sie Ihre Absicht mitgeteilt haben, sich stärker am Projekt zu beteiligen. Das bedeutet auch, dass Sie zusätzliche Verantwortlichkeiten und Rechte haben, wie unten erläutert:

- Eine Person in einem Team wird üblicherweise für ihre jeweiligen Interessengebiete in die Datei [CODEOWNERS](https://github.com/mdn/content/blob/main/.github/CODEOWNERS) aufgenommen.

- Wenn ein Pull Request Dateien in Ihrem Verantwortungsbereich betrifft, werden Sie basierend auf der CODEOWNERS-Datei mithilfe des [Lastverteilungsalgorithmus](https://docs.github.com/en/organizations/organizing-members-into-teams/managing-code-review-settings-for-your-team#routing-algorithms) von GitHub automatisch als Reviewer zu einem Pull Request hinzugefügt.

- Mitglieder eines Teams haben einen erweiterten Repository-Zugriff. Repository-Berechtigungen werden nur für die Repositories vergeben, auf die ein Mitglied Zugriff benötigt.

Zu den Teams in der [MDN-GitHub-Organisation](https://github.com/orgs/mdn/teams) gehören:

- `@Core`: Kernteam von MDN Web Docs
- `@mdn-community-engagement`: Personen, die für die Community-Interaktion in unseren Repositories verantwortlich sind
- `@mdn-product`: Personen, die für das Produkt MDN Plus verantwortlich sind
- `@localization-team-leads`: Personen, die unsere einzelnen Lokalisierungsteams leiten
- `@OWD`: Mitwirkende der gemeinnützigen Organisation Open Web Docs
- `@sre`: Site-Reliability-Engineers, die MDN Web Docs unterstützen
- `@yari-content`: Das übergeordnete Team für alle Content-Reviewer von MDN Web Docs
  - Es gibt ein Unterteam für die verschiedenen Themenbereiche — Barrierefreiheit, Add-ons, CSS, HTML, HTTP, JavaScript, SVG, Web API und WebAssembly. Beispiele sind `@yari-content-css` und `@yari-content-svg`.
  - Es gibt auch Unterteams für verschiedene Sprachen — brasilianisches Portugiesisch, Chinesisch, Französisch, Japanisch, Koreanisch, Russisch und Spanisch. Beispiele sind `@yari-content-fr` und `@yari-content-ko`.

Um Mitglied eines Teams zu werden, müssen Sie:

- Zustimmen, unsere [Community Participation Guidelines](https://www.mozilla.org/en-US/about/governance/policies/participation/) einzuhalten.
- Zustimmen, Mozillas [Commit Access Requirements](https://www.mozilla.org/en-US/about/governance/policies/commit/requirements/) einzuhalten.
- [Zwei-Faktor-Authentifizierung](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication) (2FA) für Ihr GitHub-Konto einrichten.
