Der Erfolg und das Wachstum des Projekts MDN Web Docs sind zu einem großen Teil unserer Community von Mitwirkenden zu verdanken. Einige Mitwirkende wenden einen Teil ihrer Zeit dafür auf, die täglichen Aufgaben beim Betrieb von MDN Web Docs zu unterstützen. Änderungen an der Website, einschließlich Wartungsarbeiten, werden von Angestellten, Auftragnehmenden und einem Netzwerk von Partnern vorgenommen, die sich für den Zustand, das Wachstum und die Pflege von MDN Web Docs einsetzen. Das Projekt stützt sich stark auf [Rollen](#rollen) und [Teams](#teams) in der [MDN-Organisation auf GitHub](https://github.com/mdn), um Änderungen dieser verschiedenen Gruppen zu verwalten und zu integrieren. Eine Liste der aktuellen Organisationsmitglieder finden Sie unter [github.com/orgs/mdn](https://github.com/orgs/mdn/people).

Beiträge aus der Community sind für dieses Open-Source-Projekt von großem Wert.
Mitwirkende können ihre Arbeit an MDN Web Docs nutzen, um ihre Schreib-, technischen und Teamfähigkeiten sowie ihre Fähigkeit zur Zusammenarbeit mit Menschen unterschiedlicher Herkunft zu zeigen. Dieser Abschnitt beschreibt die Rollen, die Sie bei Ihrer freiwilligen Mitarbeit am Projekt MDN Web Docs übernehmen können.

## Rollen

Im Projekt MDN Web Docs können Sie die Rolle eines [Mitwirkenden](#mitwirkende), eines [Organisationsmitglieds](#organisationsmitglied), eines [Maintainers](#maintainer) oder eines [Owners](#owner) übernehmen. Der Weg von einer Rolle zur nächsten erfolgt schrittweise.
Wenn Ihre Verantwortlichkeiten zunehmen, können Sie mehrere Rollen gleichzeitig ausüben.
Rollen wie die eines [eingeladenen Experten](#eingeladene_experten) können Sie auch direkt übernehmen, wenn Sie Fachwissen in einem bestimmten Bereich nachgewiesen haben.

Unabhängig davon, welche Rolle Sie in diesem Projekt übernehmen, sind Sie immer auch [Mitwirkender](#mitwirkende).
Die Rolle als **Mitwirkender** bildet die Grundlage für alle anderen Rollen.
In welcher Funktion Sie auch immer an diesem Projekt arbeiten: Sie müssen die Anforderungen an Mitwirkende erfüllen.

### Mitwirkende

Mitwirkende, auch _Community-Teilnehmende_ genannt, bringen ihre Zeit, Fähigkeiten, Meinungen und Ideen in das Projekt ein.
Sie arbeiten direkt am Projekt und schaffen einen Mehrwert dafür.
Neben dem Schreiben und Testen von Code gehören dazu das Erstellen und Aktualisieren von Dokumentation, Recherchen, das Beheben von Fehlern und die Unterstützung anderer Community-Mitglieder.

Je nachdem, wie häufig Sie Beiträge leisten, sind Sie gelegentlich oder regelmäßig mitwirkend.
Wenn Sie das Projekt in erheblichem Maße voranbringen, können Sie für eine [besondere Vorstellung als Mitwirkender](#besonders_vorgestellte_mitwirkende) nominiert oder zum [Organisationsmitglied](#organisationsmitglied) ernannt werden.

Wenn Sie neu hier sind und mitwirken möchten, lesen Sie unseren [Leitfaden für den Einstieg](/de/docs/MDN/Community/Getting_started) und sehen Sie sich die [Repositories der MDN-Organisation auf GitHub](https://github.com/orgs/mdn/repositories) an.

Als Mitwirkender können Sie sich auf folgende Weise am Projekt beteiligen:

- An Diskussionen der Community über die [Kommunikationskanäle](/de/docs/MDN/Community/Communication_channels) teilnehmen.
- Andere Mitwirkende bei ihren Pull Requests und Issues unterstützen oder neue Mitwirkende betreuen.
- Fehler melden. Weitere Informationen finden Sie unter [Die wichtigsten Repositories](/de/docs/MDN/Community/Our_repositories).
- Issues kommentieren, um Diskussionen zu einer konstruktiven Lösung zu führen.
- Offene Issues bearbeiten, beispielsweise im Repository [`content`](https://github.com/mdn/content/issues), indem Sie [Pull Requests](/de/docs/MDN/Community/Pull_requests) einreichen.
- An Community-Veranstaltungen teilnehmen.
- Helfen, das MDN-Projekt bekannter zu machen.

**Anforderungen:**

Um mitzuwirken, müssen Sie:

- [Mozillas Verhaltenskodex](https://www.mozilla.org/en-US/about/governance/policies/participation/) einhalten.
- Die jeweiligen Richtlinien der einzelnen Repositories befolgen. Projektspezifische Hinweise oder Richtlinien finden Sie gegebenenfalls in der Datei `CONTRIBUTING.md` im Stammverzeichnis des Projekt-Repositories.
- Verantwortung für Ihre Beiträge übernehmen. Prüfen Sie vor dem Einreichen alles und testen Sie jeglichen Code, unabhängig davon, mit welchen Werkzeugen Sie ihn erstellt haben.

**Berechtigungen:**

Mitwirkende erhalten folgende Berechtigungen:

- Einladungen zu Veranstaltungen für Mitwirkende.
- Die Möglichkeit, [Organisationsmitglied](#organisationsmitglied) zu werden.

### Organisationsmitglied

[Organisationsmitglieder](https://github.com/orgs/mdn/people) sind erfahrene [Mitwirkende](#mitwirkende), die sich regelmäßig am Projekt MDN Web Docs beteiligen und Beiträge leisten.
Von ihnen wird erwartet, dass sie im Interesse des Projekts handeln.

**Anforderungen:**

Um Organisationsmitglied zu werden, müssen Sie mindestens eine der folgenden Anforderungen erfüllen:

- Mindestens zwei zusammengeführte Pull Requests eingereicht haben, die mindestens zwei Issues beheben.
- Mindestens zwei Monate lang zu Projekten von MDN Web Docs beigetragen haben.
- In mindestens einem Projektbereich aktiv mitgewirkt haben.

Die folgenden beiden Anforderungen sind verpflichtend:

- Die [Zwei-Faktor-Authentifizierung](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication) für Ihr GitHub-Konto aktiviert haben.
- [Signierte Commits](https://docs.github.com/en/authentication/managing-commit-signature-verification/signing-commits) aktiviert haben.

**Berechtigungen:**

Organisationsmitglieder haben Berechtigungen auf [Organisationsebene](https://github.com/mdn) bei GitHub.

### Maintainer

Maintainer sind erfahrene [Mitwirkende](#mitwirkende), die für ein oder mehrere Projekte bei MDN verantwortlich sind.
Von ihnen wird erwartet, dass sie an Entscheidungen über die Richtlinien und Prioritäten des Projekts mitwirken. Informationen zum Nominieren einer Person als Maintainer finden Sie im entsprechenden [Verfahren](#maintainer_nominieren).

Als Maintainer übernehmen Sie folgende Aufgaben:

- Prioritäten für das Projekt festlegen, für das Sie verantwortlich sind.
- An Community-Treffen teilnehmen.
- Neue und bestehende Mitwirkende in allen anderen Rollen betreuen.
- Entsprechend Ihren Fähigkeiten in Ihrem Projektbereich Verbesserungen vorschlagen, genehmigen oder umsetzen, und zwar in folgenden Bereichen:
  - Code und Infrastruktur
  - Inhalte
  - Prozesse

**Anforderungen:**

Um Maintainer werden zu können, müssen Sie mindestens eine der folgenden Anforderungen erfüllen:

- Mindestens sechs Monate Erfahrung als [eingeladener Experte](#eingeladene_experten) gesammelt haben.
- Umfassende Kenntnisse des Projekts in mehreren Bereichen nachgewiesen haben.
- Bewiesen haben, dass Sie unabhängig vom Einfluss anderer Mitglieder Entscheidungen zum Wohl des Projekts treffen können.
- Andere Mitwirkende kompetent betreut haben.
- Sich bereit erklärt haben, mindestens 16 Stunden pro Monat am Projekt zu arbeiten.
- An dem Community-Treffen teilgenommen haben, das alle zwei Monate stattfindet.

> [!NOTE]
> Wenn Sie jemanden für diese Rolle für geeignet halten, können Sie die Person [als Maintainer nominieren](#maintainer_nominieren).

**Berechtigungen:**

Maintainer dürfen Pull Requests genehmigen und zusammenführen.

### Owner

Owner verfügen über weitreichende Berechtigungen, um Benutzer und [GitHub-Teams](https://github.com/orgs/mdn/teams) zu verwalten, den Zugriff auf Repositories der [MDN-Organisation](https://github.com/mdn) zu verwalten, Repository-Einstellungen zu pflegen und Änderungen in die Produktionsumgebung zu übertragen.
Für Owner gelten sämtliche Anforderungen der anderen Rollen für Mitwirkende.

> [!NOTE]
> Die Rolle als Owner ist derzeit auf Mitarbeitende von Mozilla beschränkt.

**Anforderungen:**

Zusätzlich zu den Pflichten der anderen Rollen für Mitwirkende haben Owner folgende Aufgaben:

- Die Normen des MDN-Teams einhalten und durchsetzen, einschließlich der [Richtlinien zur Beteiligung an der Community](https://www.mozilla.org/en-US/about/governance/policies/participation/) und der [Mozilla-Richtlinien](https://www.mozilla.org/en-US/about/governance/policies/).
- Die Richtlinien der MDN-Organisation befolgen und mit gutem Beispiel vorangehen.
- Neue Richtlinien über den [Pull-Request-Prozess](/de/docs/MDN/Community/Pull_requests) vorschlagen, dokumentieren und umsetzen.
- Issues und Diskussionen in der gesamten MDN-Organisation verfolgen und sich daran beteiligen.
- Sicherstellen, dass ein Issue oder Pull Request innerhalb einer Woche Rückmeldung von mindestens einem Mitglied erhält.
- Nicht mehr gepflegte Repositories [archivieren](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories) oder löschen.
- GitHub-Funktionen besprechen, die zu verwendenden Funktionen auswählen und Entscheidungen dokumentieren.

**Berechtigungen:**

Owner können:

- Nach Bedarf Owner und Mitglieder der Organisation hinzufügen und entfernen.
- Nach Bedarf Mitarbeitende mit Zugriff auf bestimmte Repositories hinzufügen und entfernen.
- Nach Bedarf Repositories hinzufügen, sowohl als neue Projekte als auch durch Übertragung.

## Besondere Rollen

Einige Rollen für Mitwirkende haben differenziertere Verantwortlichkeiten und besondere Voraussetzungen. Dazu gehören [besonders vorgestellte Mitwirkende](#besonders_vorgestellte_mitwirkende), [eingeladene Experten](#eingeladene_experten) und [Community-Manager](#community-manager).

### Besonders vorgestellte Mitwirkende

Besonders vorgestellte Mitwirkende sind Personen, die sich mit ihren Beiträgen zu MDN Web Docs in außergewöhnlichem Maße engagiert haben.
Ihre Beiträge können Pull Requests zur Verbesserung des Projekts sein, die Unterstützung von Community-Mitgliedern über verschiedene [Kommunikationskanäle](/de/docs/MDN/Community/Communication_channels) oder Lernforen oder Rückmeldungen zu GitHub-Issues und Pull Requests.

Jeden Monat stellen wir eine mitwirkende Person auf der [MDN-Website](/en-US/) besonders vor.
Im Abschnitt zum [Verfahren](#mitwirkende_für_eine_besondere_vorstellung_nominieren) erfahren Sie, wie Sie jemanden dafür nominieren können.

### Eingeladene Experten

Eingeladene Experten haben sich bei MDN durch ihre Beiträge, ihre Teilnahme an Diskussionen und Reviews oder durch nachgewiesene Kenntnisse in einem Fachgebiet ausgezeichnet.
Sie sind für ein bestimmtes Themengebiet oder eine Komponente des MDN-Projekts verantwortlich.
Zu ihren Aufgaben gehören das Prüfen und Genehmigen von Pull Requests in ihrem Themen- oder Projektbereich, das Beantworten technischer Fragen und die allgemeine Pflege ihres jeweiligen Projektbereichs. Im Abschnitt zum [Verfahren](#eingeladene_experten_nominieren) erfahren Sie, wie Sie jemanden als eingeladenen Experten nominieren können.

Zusätzlich zu den Aufgaben eines [Organisationsmitglieds](#organisationsmitglied) sind eingeladene Experten für Folgendes verantwortlich:

- Den [Prozess zur Überprüfung von Pull Requests](/de/docs/MDN/Community/Pull_requests#reviewing_a_pull_request) befolgen.
- Pull Requests in ihrem Themengebiet prüfen.
- Anderen Mitwirkenden helfen, Reviewer zu werden.

Wenn Pull Requests in ihrem Themengebiet eröffnet werden, werden eingeladene Experten automatisch als Reviewer zugewiesen.
Gibt es in einem Themengebiet mehrere Experten, werden ihnen Pull Requests anhand einer [Strategie zur Lastverteilung](https://docs.github.com/en/organizations/organizing-members-into-teams/managing-code-review-settings-for-your-team#about-auto-assignment) zugewiesen.

**Anforderungen:**

Um eingeladener Experte werden zu können, müssen Sie mindestens eine der folgenden Anforderungen erfüllen:

- Fundierte Kenntnisse in einem bestimmten Themengebiet nachgewiesen haben.
- Sich verpflichtet haben, Verantwortung für das Ihnen zugewiesene Themengebiet zu übernehmen.
- Neue und gelegentlich Mitwirkende unterstützt und ihnen geholfen haben, Pull Requests für das Zusammenführen vorzubereiten.
- An dem Community-Treffen teilgenommen haben, das alle zwei Monate stattfindet.

**Berechtigungen:**

Eingeladene Experten werden dem [Team für eingeladene Experten](https://github.com/orgs/mdn/teams/invited-experts-and-co-maintainers) und dem entsprechenden Themen- oder Projektteam hinzugefügt. Sie können:

- Auf das erforderliche Repository zugreifen, um Commits vorzunehmen sowie Pull Requests zu genehmigen und zusammenzuführen.
- Andere Mitglieder als eingeladene Experten empfehlen und über deren Aufnahme abstimmen.
- An der wöchentlichen Redaktionsbesprechung von MDN Web Docs teilnehmen.

### Community-Manager

Community-Manager nehmen in vielerlei Hinsicht eine eigenständige Rolle ein.
Sie haben viele der gleichen Aufgaben wie [Maintainer](#maintainer).
Darüber hinaus sind Community-Manager für Folgendes verantwortlich:

- Meldungen über Verstöße gegen unseren [Verhaltenskodex](https://github.com/mdn/mdn-community/blob/main/CODE_OF_CONDUCT.md), die [Richtlinien zur Beteiligung an der Community von Mozilla](https://www.mozilla.org/en-US/about/governance/policies/participation/), bearbeiten und über angemessene Maßnahmen entscheiden.
- Community-Veranstaltungen organisieren und durchführen.
- Projektbesprechungen mit Community-Bezug organisieren.
- Medienstrategien festlegen, um das MDN-Projekt bekannter zu machen.
- Den Einstieg neuer Mitwirkender gestalten und umsetzen.
- Neue Mitwirkende und Benutzer einarbeiten.
- Für den Zustand und das Wohlergehen des MDN-Projekts und aller Beteiligten sorgen.
- Automatisierungsmöglichkeiten erkennen und bei ihrer Umsetzung helfen, um die langfristige Tragfähigkeit des Projekts zu verbessern.
- Sich mit Mitwirkenden und Partnern austauschen und für gute Beziehungen zu ihnen sorgen.
- Bei Bedarf beim Sichten von Issues und beim Prüfen von Pull Requests helfen.
- Alle [Kommunikationskanäle](/de/docs/MDN/Community/Communication_channels) im Blick behalten.
- Mitwirkende hervorheben, die außergewöhnliche Arbeit geleistet und/oder besonderes Engagement für das MDN-Projekt gezeigt haben.

## Verfahren

Lesen Sie nach, wer [Maintainer](#maintainer) werden kann.

1. Klicken Sie auf der Registerkarte `Issues` im Repository `mdn/mdn` rechts auf die Schaltfläche [**New issue**](https://github.com/mdn/mdn/issues/new/choose).
2. Klicken Sie unter „Nominate a maintainer“ auf die Schaltfläche **Get started**.
3. Tragen Sie die Beiträge der Person, die Sie nominieren, in das Formular ein und senden Sie es ab.

### Eine Rolle abgeben oder den Emeritus-Status beantragen

Lebensumstände ändern sich, und damit kann sich im Laufe der Zeit auch ändern, wie viel Zeit Sie als Mitwirkender aufbringen können. Je nach Ihrer Situation möchten Sie möglicherweise:

- Vorübergehend eine Pause vom Projekt einlegen.
- Eine weniger anspruchsvolle Rolle übernehmen.
- Sich vollständig aus dem Projekt zurückziehen und den Emeritus-Status beantragen.

In all diesen Fällen können Sie Ihre Situation und den Umfang Ihrer derzeitigen Mitarbeit gerne mit dem [MDN-Team](#das_mdn-team_kontaktieren) besprechen.

### Inaktive Mitwirkende zurückstufen oder entfernen

Mitwirkende können zurückgestuft oder aus dem Projekt ausgeschlossen werden, wenn sie ihren Verantwortlichkeiten und den Anforderungen nicht nachkommen. Dazu zählen wiederholte Phasen der Inaktivität oder ein Verstoß gegen den [Verhaltenskodex](https://github.com/mdn/mdn-community/blob/main/CODE_OF_CONDUCT.md).

Die Zurückstufung oder Entfernung einer mitwirkenden Person wird von einem Teilnehmenden während eines Maintainer-Treffens vorgeschlagen.
Die Person legt Informationen vor, die den Antrag begründen.
Nach einer Diskussion stimmen Maintainer und Community-Manager darüber ab.

Das Entfernen inaktiver Mitwirkender schützt das Projekt und seine Ergebnisse und eröffnet neuen Mitwirkenden die Möglichkeit, Aufgaben zu übernehmen.

Als Inaktivität definieren wir:

- Mindestens sechs Monate lang keine Beiträge zum Projekt.
- Mindestens drei Monate lang keine Reaktion auf Kontaktversuche.

Inaktivität schadet dem Projekt. Sie kann zu unerwarteten Verzögerungen, zum Weggang anderer Mitwirkender und zu einem Vertrauensverlust in das Projekt führen. Mitwirkende müssen aktiv sein, um mit gutem Beispiel voranzugehen und ihr Engagement für das Projekt zu zeigen.

Bitte informieren Sie das Community-Team, wenn sich Ihre zeitlichen Möglichkeiten ändern, damit Sie nicht zurückgestuft oder entfernt werden. Stattdessen können Sie sich frühzeitig dafür entscheiden, [eine Zeit lang auszusetzen oder in den Emeritus-Status zu wechseln](#eine_rolle_abgeben_oder_den_emeritus-status_beantragen).

## Teams

Wir verwalten Teams mithilfe der [GitHub-Teams-Funktion](https://docs.github.com/en/organizations/organizing-members-into-teams/about-teams). Wenn Sie einem Team hinzugefügt werden, bedeutet das, dass Sie mitgeteilt haben, sich stärker am Projekt beteiligen zu wollen. Damit sind auch zusätzliche Verantwortlichkeiten und Rechte verbunden, die im Folgenden erläutert werden:

- Mitglieder eines Teams werden üblicherweise für ihre jeweiligen Interessengebiete in die Datei [CODEOWNERS](https://github.com/mdn/content/blob/main/.github/CODEOWNERS) aufgenommen.

- Wenn ein Pull Request Dateien aus Ihrem Verantwortungsbereich betrifft, werden Sie anhand der CODEOWNERS-Datei durch den [Lastverteilungsalgorithmus](https://docs.github.com/en/organizations/organizing-members-into-teams/managing-code-review-settings-for-your-team#routing-algorithms) von GitHub automatisch als Reviewer hinzugefügt.

- Teammitglieder haben erweiterte Zugriffsrechte auf Repositories. Repository-Berechtigungen werden nur für die Repositories vergeben, auf die ein Mitglied Zugriff benötigt.

Zu den Teams der [MDN-Organisation auf GitHub](https://github.com/orgs/mdn/teams) gehören:

- `@Core`: Das Kernteam von MDN Web Docs
- `@mdn-community-engagement`: Personen, die für die Zusammenarbeit mit der Community in unseren Repositories verantwortlich sind
- `@mdn-product`: Personen, die für das Produkt MDN Plus verantwortlich sind
- `@localization-team-leads`: Personen, die unsere einzelnen Lokalisierungsteams leiten
- `@OWD`: Mitwirkende der gemeinnützigen Organisation Open Web Docs
- `@sre`: Site-Reliability-Engineers, die MDN Web Docs unterstützen
- `@yari-content`: Das übergeordnete Team für alle Reviewer von MDN-Web-Docs-Inhalten
  - Für die verschiedenen Themengebiete gibt es Unterteams: Barrierefreiheit, Add-ons, CSS, HTML, HTTP, JavaScript, SVG, Web API und WebAssembly. Beispiele sind `@yari-content-css` und `@yari-content-svg`.
  - Außerdem gibt es Unterteams für verschiedene Sprachen: brasilianisches Portugiesisch, Chinesisch, Französisch, Japanisch, Koreanisch, Russisch und Spanisch. Beispiele sind `@yari-content-fr` und `@yari-content-ko`.

Um Mitglied eines Teams zu werden, müssen Sie:

- Sich bereit erklären, unsere [Richtlinien zur Beteiligung an der Community](https://www.mozilla.org/en-US/about/governance/policies/participation/) einzuhalten.
- Sich bereit erklären, Mozillas [Anforderungen für Commit-Zugriff](https://www.mozilla.org/en-US/about/governance/policies/commit/requirements/) einzuhalten.
- Die [Zwei-Faktor-Authentifizierung](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication) (2FA) für Ihr GitHub-Konto einrichten.
