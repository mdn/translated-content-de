Der Erfolg und das Wachstum des Projekts MDN Web Docs sind zu einem großen Teil unserer Community von Mitwirkenden zu verdanken. Einige Mitwirkende widmen einen Teil ihrer Zeit den täglichen Aufgaben, die für den Betrieb von MDN Web Docs anfallen. Änderungen an der Website, einschließlich Wartungsarbeiten, werden von Angestellten, Auftragnehmenden und einem Netzwerk von Partnern vorgenommen, die sich für den Zustand, das Wachstum und die Pflege von MDN Web Docs einsetzen. Das Projekt stützt sich bei der Verwaltung und Einbindung der Änderungen dieser verschiedenen Gruppen stark auf [Rollen](#rollen) und [Teams](#teams) in der [MDN-Organisation auf GitHub](https://github.com/mdn). Eine Liste der aktuellen Mitglieder der Organisation finden Sie unter [github.com/orgs/mdn](https://github.com/orgs/mdn/people).

Beiträge aus der Community sind für dieses Open-Source-Projekt von unschätzbarem Wert.
Mitwirkende können ihre Arbeit an MDN Web Docs nutzen, um ihre Fähigkeiten im Schreiben, ihre technischen Kenntnisse und ihre Fähigkeit zur Zusammenarbeit mit Menschen unterschiedlicher Herkunft zu zeigen. Dieser Abschnitt beschreibt die Rollen, die Sie bei Ihrer freiwilligen Mitarbeit am Projekt MDN Web Docs übernehmen können.

## Rollen

Im Projekt MDN Web Docs können Sie die Rolle eines [Mitwirkenden](#mitwirkende), eines [Organisationsmitglieds](#organisationsmitglieder), eines [Maintainers](#maintainer) oder eines [Owners](#owner) übernehmen. Der Wechsel von einer Rolle zur nächsten erfolgt schrittweise.
Wenn Ihre Verantwortlichkeiten wachsen, können Sie auch mehrere Rollen gleichzeitig ausüben.
Rollen wie die eines [eingeladenen Experten](#eingeladene_experten) können Sie direkt übernehmen, wenn Sie Fachkenntnisse in einem bestimmten Bereich nachgewiesen haben.

Unabhängig davon, welche Rolle Sie in diesem Projekt übernehmen, sind Sie immer auch ein [Mitwirkender](#mitwirkende).
Die Rolle des **Mitwirkenden** bildet die Grundlage für alle anderen Rollen.
Wenn Sie in irgendeiner Funktion an diesem Projekt arbeiten, müssen Sie daher die Anforderungen dieser Rolle erfüllen.

### Mitwirkende

Mitwirkende, auch _Community-Mitglieder_ genannt, bringen ihre Zeit, Fähigkeiten, Meinungen und Ideen in das Projekt ein.
Sie arbeiten direkt am Projekt und schaffen einen Mehrwert dafür.
Neben dem Schreiben und Testen von Code zählen dazu das Erstellen und Aktualisieren von Dokumentation, Recherchen, das Beheben von Fehlern und die Unterstützung anderer Community-Mitglieder.

Je nachdem, wie häufig Sie Beiträge leisten, können Sie gelegentlich oder aktiv mitwirken.
Wenn Sie einen besonders großen Beitrag zum Projekt leisten, können Sie als [Mitwirkender im Rampenlicht](#mitwirkende_im_rampenlicht) nominiert oder zum [Organisationsmitglied](#organisationsmitglieder) ernannt werden.

Wenn Sie neu hier sind und mitwirken möchten, lesen Sie unseren [Leitfaden für den Einstieg](/de/docs/MDN/Community/Getting_started) und sehen Sie sich die [Repositorys der MDN-Organisation auf GitHub](https://github.com/orgs/mdn/repositories) an.

Als Mitwirkender können Sie sich auf folgende Weise am Projekt beteiligen:

- Nehmen Sie auf den [Kommunikationskanälen](/de/docs/MDN/Community/Communication_channels) an Diskussionen in der Community teil.
- Unterstützen Sie andere Mitwirkende bei ihren Pull Requests und Issues oder betreuen Sie neue Mitwirkende.
- Melden Sie Fehler. Weitere Informationen finden Sie bei den [wichtigsten Repositorys](/de/docs/MDN/Community/Our_repositories).
- Kommentieren Sie Issues, um Diskussionen zu einer konstruktiven Lösung zu führen.
- Bearbeiten Sie offene Issues, beispielsweise im Repository [`content`](https://github.com/mdn/content/issues), indem Sie [Pull Requests](/de/docs/MDN/Community/Pull_requests) einreichen.
- Nehmen Sie an Community-Veranstaltungen teil.
- Helfen Sie dabei, das MDN-Projekt bekannter zu machen.

**Anforderungen:**

Um mitzuwirken, müssen Sie Folgendes beachten:

- [Mozillas Verhaltenskodex](https://www.mozilla.org/en-US/about/governance/policies/participation/)
- Die jeweiligen Richtlinien der Repositorys. Projektspezifische Hinweise oder Richtlinien finden Sie gegebenenfalls in der Datei `CONTRIBUTING.md` im Stammverzeichnis des Projekt-Repositorys.

**Berechtigungen:**

Mitwirkende haben folgende Möglichkeiten:

- Einladungen zu Veranstaltungen für Mitwirkende erhalten.
- [Organisationsmitglied](#organisationsmitglieder) werden.

### Organisationsmitglieder

[Organisationsmitglieder](https://github.com/orgs/mdn/people) sind etablierte [Mitwirkende](#mitwirkende), die regelmäßig am Projekt MDN Web Docs teilnehmen und Beiträge leisten.
Von ihnen wird erwartet, dass sie im Interesse des Projekts handeln.

**Anforderungen:**

Um Organisationsmitglied zu werden, müssen Sie mindestens eine der folgenden Anforderungen erfüllen:

- Sie haben mindestens zwei zusammengeführte Pull Requests eingereicht, mit denen mindestens zwei Issues gelöst wurden.
- Sie haben mindestens zwei Monate lang zu MDN-Web-Docs-Projekten beigetragen.
- Sie haben aktiv in mindestens einem Projektbereich mitgewirkt.

Die folgenden beiden Anforderungen sind verpflichtend:

- Sie haben die [Zwei-Faktor-Authentifizierung](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication) für Ihr GitHub-Konto aktiviert.
- Sie haben [signierte Commits](https://docs.github.com/en/authentication/managing-commit-signature-verification/signing-commits) aktiviert.

**Berechtigungen:**

Organisationsmitglieder haben auf GitHub Berechtigungen auf [Organisationsebene](https://github.com/mdn).

### Maintainer

Maintainer sind etablierte [Mitwirkende](#mitwirkende), die für ein oder mehrere MDN-Projekte verantwortlich sind.
Von ihnen wird erwartet, dass sie an Entscheidungen über die Richtlinien und Prioritäten des Projekts mitwirken. Wie Sie jemanden als Maintainer nominieren können, erfahren Sie im Abschnitt zum [Verfahren](#maintainer_nominieren).

Als Maintainer übernehmen Sie folgende Aufgaben:

- Sie legen die Prioritäten für das Projekt fest, für das Sie verantwortlich sind.
- Sie nehmen an Community-Treffen teil.
- Sie betreuen neue und erfahrene Mitwirkende aller anderen Rollen.
- Je nach Ihren Fähigkeiten schlagen Sie in Ihrem Projektbereich die folgenden Verbesserungen vor, genehmigen sie oder setzen sie um:
  - Verbesserungen an Code und Infrastruktur
  - Verbesserungen an Inhalten
  - Verbesserungen an Prozessen

**Anforderungen:**

Um Maintainer werden zu können, müssen Sie mindestens eine der folgenden Anforderungen erfüllen:

- Sie haben mindestens sechs Monate Erfahrung als [eingeladener Experte](#eingeladene_experten) gesammelt.
- Sie haben umfassende Kenntnisse des Projekts in mehreren Bereichen nachgewiesen.
- Sie haben gezeigt, dass Sie unabhängig vom Einfluss anderer Mitglieder Entscheidungen zum Wohl des Projekts treffen können.
- Sie haben andere Mitwirkende besonders gut betreut.
- Sie haben sich bereit erklärt, mindestens 16 Stunden pro Monat für die Arbeit am Projekt aufzuwenden.
- Sie haben an dem alle zwei Monate stattfindenden Community-Treffen teilgenommen.

> [!NOTE]
> Wenn Sie jemanden kennen, der für diese Rolle geeignet ist, können Sie diese Person [als Maintainer nominieren](#maintainer_nominieren).

**Berechtigungen:**

Maintainer können Pull Requests genehmigen und zusammenführen.

### Owner

Owner haben weitreichende Berechtigungen, um Benutzer und [GitHub-Teams](https://github.com/orgs/mdn/teams) zu verwalten, Zugriffsrechte für die Repositorys der [MDN-Organisation](https://github.com/mdn) zu verwalten, Repository-Einstellungen zu pflegen und Änderungen in der Produktionsumgebung bereitzustellen.
Für Owner gelten sämtliche Anforderungen der anderen Rollen für Mitwirkende.

> [!NOTE]
> Die Rolle des Owners ist derzeit auf Mitarbeitende von Mozilla beschränkt.

**Anforderungen:**

Zusätzlich zu den Aufgaben der anderen Rollen für Mitwirkende haben Owner folgende Verantwortlichkeiten:

- Sie befolgen die Regeln des MDN-Teams und setzen sie durch, einschließlich der [Richtlinien für die Teilnahme an der Community](https://www.mozilla.org/en-US/about/governance/policies/participation/) und der [Mozilla-Richtlinien](https://www.mozilla.org/en-US/about/governance/policies/).
- Sie befolgen die Richtlinien der MDN-Organisation und gehen mit gutem Beispiel voran.
- Sie schlagen über das [Pull-Request-Verfahren](/de/docs/MDN/Community/Pull_requests) neue Richtlinien vor, dokumentieren sie und setzen sie um.
- Sie verfolgen Issues und Diskussionen in der gesamten MDN-Organisation und beteiligen sich daran.
- Sie stellen sicher, dass ein Issue oder Pull Request innerhalb einer Woche Rückmeldung von mindestens einem Mitglied erhält.
- Sie [archivieren](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories) oder löschen Repositorys, die nicht mehr gepflegt werden.
- Sie besprechen GitHub-Funktionen, entscheiden, welche davon verwendet werden, und dokumentieren diese Entscheidungen.

**Berechtigungen:**

Owner können:

- Bei Bedarf Owner und Mitglieder der Organisation hinzufügen und entfernen.
- Bei Bedarf Mitarbeitende zu bestimmten Repositorys hinzufügen und daraus entfernen.
- Bei Bedarf Repositorys hinzufügen, entweder als neue Projekte oder durch Übertragung.

## Besondere Rollen

Einige Rollen für Mitwirkende haben differenziertere Verantwortlichkeiten und besondere Voraussetzungen. Dazu gehören [Mitwirkende im Rampenlicht](#mitwirkende_im_rampenlicht), [eingeladene Experten](#eingeladene_experten) und [Community-Manager](#community-manager).

### Mitwirkende im Rampenlicht

Mitwirkende im Rampenlicht sind Personen, die mit ihren Beiträgen zu MDN Web Docs Außergewöhnliches geleistet haben.
Ihre Beiträge können Pull Requests zur Verbesserung des Projekts, die Unterstützung von Community-Mitgliedern auf verschiedenen [Kommunikationskanälen](/de/docs/MDN/Community/Communication_channels) oder in Lernforen sowie Rückmeldungen zu GitHub-Issues und Pull Requests umfassen.

Jeden Monat stellen wir auf der [MDN-Website](/en-US/) eine mitwirkende Person vor.
Wie Sie jemanden dafür nominieren können, erfahren Sie im Abschnitt zum [Verfahren](#mitwirkende_für_das_rampenlicht_nominieren).

### Eingeladene Experten

Eingeladene Experten haben sich bei MDN durch ihre Beiträge, ihre Beteiligung an Diskussionen und Reviews oder durch nachgewiesene Kenntnisse in einem bestimmten Fachgebiet ausgezeichnet.
Sie sind für einen bestimmten Themenbereich oder eine Komponente des MDN-Projekts verantwortlich.
Zu ihren Aufgaben gehören die Prüfung und Genehmigung von Pull Requests in ihrem Themen- oder Projektbereich, die Beantwortung technischer Fragen und die allgemeine Pflege ihres jeweiligen Projekts. Wie Sie jemanden als eingeladenen Experten nominieren können, erfahren Sie im Abschnitt zum [Verfahren](#eingeladene_experten_nominieren).

Zusätzlich zu den Verantwortlichkeiten eines [Organisationsmitglieds](#organisationsmitglieder) sind eingeladene Experten für Folgendes zuständig:

- Sie befolgen das [Verfahren zur Prüfung von Pull Requests](/de/docs/MDN/Community/Pull_requests#reviewing_a_pull_request).
- Sie prüfen Pull Requests in ihrem Themenbereich.
- Sie helfen anderen Mitwirkenden dabei, Reviewer zu werden.

Wenn in ihrem Themenbereich Pull Requests eröffnet werden, werden eingeladene Experten automatisch als Reviewer zugewiesen.
Gibt es in einem Themenbereich mehrere Experten, werden sie den Pull Requests anhand einer [Strategie zum Lastausgleich](https://docs.github.com/en/organizations/organizing-members-into-teams/managing-code-review-settings-for-your-team#about-auto-assignment) zugewiesen.

**Anforderungen:**

Um eingeladener Experte werden zu können, müssen Sie mindestens eine der folgenden Anforderungen erfüllen:

- Sie haben fundierte Kenntnisse in einem bestimmten Themenbereich nachgewiesen.
- Sie haben sich verpflichtet, die Verantwortung für den Ihnen zugewiesenen Themenbereich zu übernehmen.
- Sie haben neue und gelegentlich Mitwirkende unterstützt und ihnen geholfen, Pull Requests für die Zusammenführung vorzubereiten.
- Sie haben an dem alle zwei Monate stattfindenden Community-Treffen teilgenommen.

**Berechtigungen:**

Eingeladene Experten werden dem [Team für eingeladene Experten](https://github.com/orgs/mdn/teams/invited-experts-and-co-maintainers) und dem entsprechenden Themen- oder Projektteam hinzugefügt. Sie können:

- Auf das benötigte Repository zugreifen, um Commits vorzunehmen sowie Pull Requests zu genehmigen und zusammenzuführen.
- Andere Mitglieder als eingeladene Experten empfehlen und über ihre Aufnahme abstimmen.
- An der wöchentlichen Redaktionsbesprechung von MDN Web Docs teilnehmen.

### Community-Manager

Community-Manager haben in vielerlei Hinsicht eine eigenständige Rolle.
Sie übernehmen viele der gleichen Verantwortlichkeiten wie [Maintainer](#maintainer).
Darüber hinaus haben Community-Manager folgende Aufgaben:

- Sie bearbeiten Meldungen über Verstöße gegen unseren [Verhaltenskodex](https://github.com/mdn/mdn-community/blob/main/CODE_OF_CONDUCT.md), der den [Richtlinien von Mozilla für die Teilnahme an der Community](https://www.mozilla.org/en-US/about/governance/policies/participation/) entspricht, und entscheiden über angemessene Maßnahmen.
- Sie organisieren und leiten Community-Veranstaltungen.
- Sie organisieren projektbezogene Community-Treffen.
- Sie legen Medienstrategien fest, um das MDN-Projekt bekannter zu machen.
- Sie gestalten und implementieren den Einführungsprozess für Mitwirkende.
- Sie führen neue Mitwirkende und Benutzer ein.
- Sie sorgen für den Zustand und das Wohlergehen des MDN-Projekts und aller Beteiligten.
- Sie ermitteln Möglichkeiten zur Automatisierung, um die langfristige Tragfähigkeit des Projekts zu verbessern, und unterstützen deren Umsetzung.
- Sie treffen sich mit Mitwirkenden und Partnern und sorgen für eine gute Zusammenarbeit.
- Sie helfen gegebenenfalls bei der Sichtung von Issues und der Prüfung von Pull Requests.
- Sie behalten alle [Kommunikationskanäle](/de/docs/MDN/Community/Communication_channels) im Blick.
- Sie würdigen Mitwirkende, die außergewöhnliche Arbeit geleistet und/oder besonderes Engagement für das MDN-Projekt gezeigt haben.

1. Klicken Sie im Repository `mdn/mdn` auf der Registerkarte `Issues` rechts auf die Schaltfläche [**New issue**](https://github.com/mdn/mdn/issues/new/choose).
2. Klicken Sie unter „Nominate a maintainer“ auf die Schaltfläche **Get started**.
3. Tragen Sie in das Formular Einzelheiten zu den Beiträgen der Person ein, die Sie nominieren, und senden Sie es ab.

### Eine Rolle abgeben oder den Emeritus-Status beantragen

Lebensumstände ändern sich, und damit kann sich auch ändern, wie viel Zeit Sie für Ihre Mitarbeit aufbringen können. Je nach Situation möchten Sie vielleicht:

- Vorübergehend eine Pause vom Projekt einlegen.
- Eine weniger anspruchsvolle Rolle übernehmen.
- Sich vollständig aus dem Projekt zurückziehen und den Emeritus-Status beantragen.

In all diesen Fällen können Sie Ihre Situation und Ihre derzeitigen Möglichkeiten zur Mitarbeit gern mit dem [MDN-Team](#kontakt_zum_mdn-team) besprechen.

### Inaktive Mitwirkende zurückstufen oder entfernen

Mitwirkende können zurückgestuft oder aus dem Projekt ausgeschlossen werden, wenn sie ihre Verantwortlichkeiten und Anforderungen nicht erfüllen. Dazu gehören wiederholte Inaktivität oder ein Verstoß gegen den [Verhaltenskodex](https://github.com/mdn/mdn-community/blob/main/CODE_OF_CONDUCT.md).

Die Zurückstufung oder der Ausschluss eines Mitwirkenden wird von einem Teilnehmer während eines Maintainer-Treffens vorgeschlagen.
Der Teilnehmer legt Informationen vor, die den Antrag auf Zurückstufung oder Ausschluss begründen.
Nach einer Diskussion stimmen Maintainer und Community-Manager darüber ab.

Das Entfernen inaktiver Mitwirkender schützt das Projekt und seine Ergebnisse und eröffnet zugleich neuen Mitwirkenden die Möglichkeit, Aufgaben zu übernehmen.

Wir definieren Inaktivität wie folgt:

- Mindestens sechs Monate lang keine Beiträge zum Projekt.
- Mindestens drei Monate lang keine Reaktion auf Mitteilungen.

Inaktivität schadet dem Projekt: Sie kann zu unerwarteten Verzögerungen, zum Weggang Mitwirkender und zu einem Vertrauensverlust in das Projekt führen. Mitwirkende müssen aktiv sein, um mit gutem Beispiel voranzugehen und ihr Engagement für das Projekt zu zeigen.

Bitte informieren Sie das Community-Team, wenn sich Ihre zeitlichen Möglichkeiten ändern, damit Sie nicht zurückgestuft oder ausgeschlossen werden. Stattdessen können Sie sich selbst dafür entscheiden, [eine Zeit lang zu pausieren oder in den Emeritus-Status zu wechseln](#eine_rolle_abgeben_oder_den_emeritus-status_beantragen).

## Teams

Wir verwalten Teams mithilfe der Funktion [GitHub-Teams](https://docs.github.com/en/organizations/organizing-members-into-teams/about-teams). Wenn Sie einem Team hinzugefügt werden, bedeutet das, dass Sie Ihr Interesse an einer engeren Mitarbeit am Projekt bekundet haben. Damit gehen auch einige zusätzliche Verantwortlichkeiten und Rechte einher:

- Teammitglieder werden üblicherweise für ihre jeweiligen Interessengebiete in die Datei [CODEOWNERS](https://github.com/mdn/content/blob/main/.github/CODEOWNERS) eingetragen.

- Wenn ein Pull Request Dateien in Ihrem Zuständigkeitsbereich betrifft, werden Sie anhand der CODEOWNERS-Datei durch den [Lastausgleichsalgorithmus](https://docs.github.com/en/organizations/organizing-members-into-teams/managing-code-review-settings-for-your-team#routing-algorithms) von GitHub automatisch als Reviewer hinzugefügt.

- Teammitglieder haben erweiterte Zugriffsrechte auf Repositorys. Berechtigungen werden nur für die Repositorys vergeben, auf die ein Mitglied zugreifen muss.

Zu den Teams in der [MDN-Organisation auf GitHub](https://github.com/orgs/mdn/teams) gehören:

- `@Core`: Das Kernteam von MDN Web Docs
- `@mdn-community-engagement`: Personen, die für die Zusammenarbeit mit der Community in unseren Repositorys verantwortlich sind
- `@mdn-product`: Personen, die für das Produkt MDN Plus verantwortlich sind
- `@localization-team-leads`: Personen, die unsere einzelnen Lokalisierungsteams leiten
- `@OWD`: Mitwirkende der gemeinnützigen Organisation Open Web Docs
- `@sre`: Site-Reliability-Engineers, die MDN Web Docs unterstützen
- `@yari-content`: Das übergeordnete Team für alle Reviewer von MDN-Web-Docs-Inhalten
  - Für die verschiedenen Themenbereiche gibt es Unterteams: Barrierefreiheit, Add-ons, CSS, HTML, HTTP, JavaScript, SVG, Web API und WebAssembly. Beispiele dafür sind `@yari-content-css` und `@yari-content-svg`.
  - Außerdem gibt es Unterteams für verschiedene Sprachen: brasilianisches Portugiesisch, Chinesisch, Französisch, Japanisch, Koreanisch, Russisch und Spanisch. Beispiele dafür sind `@yari-content-fr` und `@yari-content-ko`.

Um Mitglied eines Teams zu werden, müssen Sie:

- Zustimmen, unsere [Richtlinien für die Teilnahme an der Community](https://www.mozilla.org/en-US/about/governance/policies/participation/) einzuhalten.
- Mozillas [Anforderungen für Commit-Zugriff](https://www.mozilla.org/en-US/about/governance/policies/commit/requirements/) zustimmen.
- Die [Zwei-Faktor-Authentifizierung](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/configuring-two-factor-authentication) (2FA) für Ihr GitHub-Konto einrichten.
